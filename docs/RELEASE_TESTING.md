# MiraBox Studio Next

用于 Windows 上 MiraBox D69 / D92 屏幕的内容管理与控制软件。桌面宿主使用 .NET 8 / WPF / WebView2，主要界面沿用本仓库原有的 D Studio React 原型；设备按真实序列号独立输出。

## 已接通的功能

- 图片、视频导入与管理副本；收藏、重命名、回收与恢复。
- 原型主题编辑器、文字/图片/形状图层、多规格布局、时钟、日期与星期。
- 视频背景、视频图层与原型 CSS 动效合成；同次会话暂停继续保持视频时间轴。方向切换或重启后视频从头播放。
- 图片、视频、主题混播；每项时长、顺序/随机、暂停与上下项。
- 原生后台定时、执行记录、一次性去重、冲突与缺失目标处理。
- 每台设备独立的软件画面调暗、黑帧待机及恢复；不把这些操作当作背光亮度或硬件断电控制。
- 含素材依赖的完整备份与单工程包；导入前校验、冲突 ID 重映射、恢复日志与上一份有效快照。
- 渲染心跳、超时、异常重建、系统电源事件处理及启动恢复。

插件真实数据、账号/支付、真实在线商店和真实桌面录屏仍未接入。相应区域保留原型展示并标明示例或未支持。功能核对详见 [docs/FEATURE_AUDIT.md](docs/FEATURE_AUDIT.md)。1123 HTML 不属于本版本源码或发布内容。

## Windows 内测安装版

当前安装测试版为 0.2.3，使用 Windows 10 2004 或以上版本的 x64 系统。安装包内置 .NET 运行时，安装时检测 WebView2；缺失时使用微软引导程序联网安装。安装程序为未签名内测版。

运行 `artifacts/release/0.2.3/MiraBoxStudioNext-0.2.3-win-x64-Setup.exe`，默认按当前用户安装到 `%LOCALAPPDATA%/Programs/MiraBox Studio Next`。选择“为所有用户安装”时申请管理员权限，支持 Program Files 等系统目录。安装器提前检查目标目录的写入权限，并创建开始菜单与桌面快捷方式。卸载保留 `%LOCALAPPDATA%/MiraBoxStudio.Next` 中的用户工程和素材。

构建安装包需要 Inno Setup 6 编译器，运行 `./package-release.ps1`，或通过 `-Iscc` 指定编译器路径。脚本检查微软引导程序签名，清理对应版本的构建输出后重新发布。安装测试和现场待验项目见 [发布验收记录](docs/RELEASE_TESTING.md)。

## 构建与运行

需要 Windows 10/11、.NET 8 SDK、Node.js 22.12 或以上版本，以及 Microsoft Edge WebView2 Runtime。运行构建好的程序需要 .NET 8 Windows Desktop Runtime。

```powershell
npm ci --ignore-scripts
npm --prefix d-studio ci
./build.ps1
./artifacts/current/MiraBox.App.exe
```

构建前请关闭正在使用该输出目录的程序。`build.ps1` 构建前端与宿主，输出到 `artifacts/current`。`frontend` 是保留的早期参考代码，当前构建入口为 `d-studio`。

默认数据目录为 `%LOCALAPPDATA%/MiraBoxStudio.Next`。`MIRABOX_DATA_DIR` 可指定独立工作区，不同工作区使用不同进程互斥标识。不要将日常数据目录、WebView2 用户目录、备份包或密钥加入 Git。

## 备份与迁移

请先保存编辑器中的修改。设置页提供“导出完整备份”“导出工程包”和“导入或恢复备份包”。包包含真实素材字节和 SHA256 清单，不只是引用原路径的 JSON。

- **合并导入**保留现有内容；冲突主题、列表与定时生成新 ID，关联引用一起重映射，工程编辑标识独立。
- **恢复备份**替换索引及设置，保留已有素材文件，先暂停设备输出和定时，供用户核对后恢复。
- 缺少素材时导出会报出缺失依赖，不把不完整包伪装成成功备份。
- JSON 损坏时优先恢复上一份有效快照并保留损坏原件。设备/调度状态无法启动时提供原生恢复窗口。
- 仅导出 `.d92theme.json` 是工程描述，跨电脑迁移请使用包含依赖的 `.mirabox` 工程包。

换电脑后，同一设备的序列号仍是绑定依据；更换实际设备时应在列表、定时界面重新绑定，不能按“第二块屏幕”猜测目标。

## 结构

| 目录 | 用途 |
|---|---|
| `d-studio` | 当前 React 原型界面、编辑器及后台场景画布 |
| `src/MiraBox.App` | 新桌面桥接、设备会话、合成、备份和恢复；保留部分 V67 引擎代码 |
| `src/MiraBox.Core` | 原生资源/会话基础模型 |
| `dependencies/DeskDisplay` | 随源码附带的显示与 USB 引擎，构建无需访问开发者原工作树 |
| `tests` | 离线检查和可重复使用的生成视频样本 |
| `tools-*.cjs` / `tools-*.ps1` | 实际 WebView2、USB 与持续运行验收工具 |

实现使用 WebView2 的[图像捕获接口](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.capturepreviewasync)及 [CDP 场景帧流](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-startScreencast)，复用原型布局。JPEG 编码在独立 STA 工作线程执行；界面预览与设备发送频率分开。合成输出有设备/主机性能上限，不能以 USB 重发次数代替新画面的合成帧率。

原生视频在列表切换间复用已暂停、清空 Source 的播放器，闲置缓存最多四个；素材、GPU 帧和读回缓冲仍在每次结束时释放，失败播放器不回池，退出时关闭缓存。该策略用于避免反复创建原生播放队列的资源增长，并由独立循环及实机采样验证。[MediaPlayer 的官方类型约定](https://learn.microsoft.com/en-us/uwp/api/windows.media.playback.mediaplayer)允许 Agile / Both 线程模型；本程序仍保持每次租用独占并串行解码。

## 0.2.4 原生桌面采集

编辑器“添加”中的区域截图和区域录屏已接入 C# 桌面宿主。截图保存 PNG，录屏通过 ScreenRecorderLib 6.6.0 使用 Windows 原生捕获与 Media Foundation，优先硬件 H.264 编码，保存 MP4 和首帧 PNG 封面。录屏为 30 fps、包含鼠标、无音轨。H.264 选区尺寸向下对齐到偶数像素。

选区支持拖动创建、拖动框内移动、方向键移动、Ctrl+方向键调整尺寸、Shift 加速、P 切换比例、I 切换包含本软件、Tab 切换显示器、Enter 确认、Esc 取消。单次捕获限定在一台显示器内。停止使用悬浮工具条或 Ctrl+Shift+F10，倒计时期间停止会取消录制。

本机已验证截图插入独立图层、录屏倒计时及快捷键停止、首帧封面、MP4 浏览器解码、保存和重新编辑后视频图层持久存在、截图取消恢复编辑器。原生编码测试已生成 1920×462 和 480×1280 的 MP4。现有主题宿主 17 项回归检查通过。

待外部环境验收包括双屏混合 DPI、其他显卡和缺少 VC++ 运行库的干净电脑。安装包包含微软签名的 VC++ x64 安装程序，缺少运行库时申请系统安装授权。

## 0.2.5 录制控制交互修复

框选后可以点击“确认选区”，然后显示独立可见工具条。“开始录制”点击后显示 3、2、1 倒计时，随后显示录制计时及“结束录制”。录制前与倒计时期间可以取消。已通过实际鼠标点击验证确认、开始、倒计时、结束及 MP4/首帧封面回传。

控制工具条使用可见窗口，保持在选区外侧优先位置。取消了控制工具条的捕获排除属性，以便远程桌面使用者看到控制按钮。选区覆盖整个显示器、没有外侧空间时，工具条可能进入成片。选区红框继续保持鼠标穿透与捕获排除。

## 0.2.6 首页编辑保存同步

从首页编辑当前素材后，“保存”写入工程并刷新原设备当前方向的输出缓存。对于本地壁纸首次转换出的自制主题，使用源主题 ID 校验当前输出，再切换至保存后的自制主题 ID。保存后继续编辑会使用更新后的输出引用。设备暂停状态保留，其他方向和其他设备的输出引用独立保存。设备方向或当前内容已切换时跳过同步。

D69 横屏已通过首页编辑、增加文字图层、保存、返回、预览变化、标题变化和暂停保留的实机桥接回归。已覆盖本地图片首次保存为自制主题与现有自制主题保存。回归脚本为 tools-home-save-refresh.cjs，使用隔离工作区和真实 D69。

## 0.2.7 编辑目标标识冲突修复

原始本地素材新建自制主题时，编辑会话分配独立且稳定的保存 ID，模板 ID 作为工程内容标识保留。编辑已有自制主题继续使用该资源 ID。编辑器组件按资源 ID 区分会话，防止相同模板 ID 的不同素材共享编辑状态。重命名同步工程名称，打开旧工程时以资源当前名称为准。

使用同模板 ID 的原始素材和已有自制主题验证独立保存、其他主题未改动、重复保存 ID 稳定、旧工程重命名后打开及保存名称正确。结果见 tools-editor-identity.cjs。本次没有修改用户现有主题标识或清理历史输出快照。

## 0.2.8 竖屏布局与后台画布尺寸

编辑器首次进入按当前设备型号及方向选择精确尺寸布局，缺少精确尺寸时选择同方向布局。后台 WebView2 使用设备分辨率的独立 CSS 视口，截图按目标范围获取并验证像素宽高。桌面显示器高度限制导致的 480×1100 渲染画面不再缩放填入 480×1280。

原生 WebView2 测试通过 480×1280、462×1920、1280×480、1920×462 四种输出尺寸和纯色顶边检查。用户主题 11 原生截图为 480×1280，已目视核对上下画面。D69 竖屏从资源库进入编辑器，默认选择“D69 竖屏 · 480×1280”的界面测试通过。

## 0.2.9 编辑器保存、草稿及撤销回归

资源库以当前设备尺寸、同方向、全部素材循环，按钮显示下一次操作。对应按钮依次为“显示同向”“显示全部”“显示当前”。

首次保存后保留编辑会话，保存期间的新修改保持在画布与草稿内，可继续保存。异步结果只更新发起保存的编辑会话。工程 JSON 在更改当前画布前校验背景、布局、尺寸及图层结构。丢弃退出清理草稿，撤销回已保存内容后清理过时草稿。撤销/重做携带布局尺寸，恢复正确的画布选择；未保存状态比较工程内容并排除修改时间字段。

隔离工作区通过 tools-editor-regressions.cjs 的 17 项界面回归，包含延迟首次保存、随后继续保存、三种无效工程导入、草稿丢弃及清理、撤销/重做、完整三档筛选循环。tools-editor-identity.cjs 的同源主题独立性回归通过。

## 0.2.9 编辑器五项修复与资源库筛选

编辑器为每次进入建立独立且稳定的会话，首次保存和异步回传保留保存期间的新修改。草稿丢弃清理本会话记录。未保存状态比较实际内容并排除修改时间；撤销回已保存内容会移除过时草稿。历史记录包含画布尺寸，撤销和重做恢复对应布局。

JSON 导入先验证背景、布局尺寸和图层结构，失败时保留当前工程。较早工程中缺少的可选元数据、图层默认属性、锁定和名称映射由已有工程/图层默认逻辑补齐。

资源库状态顺序为当前设备尺寸 → 相同横竖方向 → 全部素材 → 当前设备尺寸，按钮显示下一次操作，分别为显示同向 → 显示全部 → 显示当前。

19 项 tools-editor-regressions.cjs 界面回归全部通过，包括人为延迟首次保存、继续保存、无效 JSON 拒绝、较早格式正常导入后选择与删除图层、草稿丢弃、撤销/重做和筛选完整循环。同源主题独立性 tools-editor-identity.cjs 回归通过。
